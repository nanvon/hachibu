# Hachibu v1 技术设计

更新日期：2026-10-26

本文是 v1 写代码的依据。`macOS菜单栏电池监控应用技术方案调研.md` 是调研记录，两者冲突时以本文为准。字段和数值在 MacBookPro18,1（M1 Pro）、macOS 27.0.1、140W 充电器、接电未充电状态下实测。

## 1. 基本信息

| 项目 | 值 |
|---|---|
| Bundle ID | `io.github.nanvon.hachibu`，首次发布后不能改 |
| Apple Developer 账号 | 不使用；ad-hoc 签名，见第 17 节 |
| 代码仓库 | GitHub `nanvon/hachibu` |

调研文档末尾的 7 个问题按以下结论写入本文，有异议再改：缺失指标显示“—”；健康度以系统最大容量为主，容量比放详情；功率按硬件实际刷新显示，并标注更新时间；温度展示和提醒都用同一个读数；首版不做概览页，“耗电量”改为“系统功率”；接受休眠缺口和定时器偏移。

依赖关系：`FeatureUI → BatteryCore, HistoryStore`；`HistoryStore → BatteryCore, GRDB`；App 依赖全部三个。`BatteryCore` 和 `HistoryStore` 不依赖 AppKit 或 SwiftUI，可以用 `swift test` 单独测试。

本地化：`Package.swift` 设 `defaultLocalization: "en"`。界面文案只出现在 `FeatureUI` 和 App target；`BatteryCore` 输出枚举值（如状态），由 `FeatureUI` 转成文字。

并发：UI 状态放在 `@MainActor` 的 `@Observable` 对象里；完整硬件读取和数据库写入在采样 actor 中执行。IOPS 电源状态另有独立的快速读取任务，避免等待 PowerUI 等完整采样接口；两类结果回到主线程，按读取开始时间合并。

签名：开发期 Debug 用本地签名（Sign to Run Locally），别人 clone 后不改工程就能运行；想用自己的证书时在 `Local.xcconfig` 里配置。`ENABLE_HARDENED_RUNTIME = YES` 对所有配置设置；但用本地签名（`CODE_SIGN_IDENTITY = -`）时 Xcode 不会给 codesign 加 runtime 选项。发布包由 `scripts/build.sh` 不签名构建后，逐层用 `codesign --sign - --options runtime` 做 ad-hoc 签名，Hardened Runtime 在发布包上生效，所以验证 Hardened Runtime 下的行为（例如读取 IOKit、运行 `system_profiler`）要用 `scripts/build.sh` 的产物。entitlements 文件声明关闭 Sandbox，并关闭 Library Validation（ad-hoc 签名没有 Team ID，不关闭则无法加载 Sparkle framework），不加其他权限。

仓库里不放任何密钥：Sparkle EdDSA 私钥只放在本地钥匙串和 GitHub secret 里。

## 5. 数据来源

每个指标只用一个来源。读不到、类型不对或者是哨兵值时，界面显示“—”，数据库存 `NULL`。

| 指标 | 来源 | 单位 | 本机实测值 |
|---|---|---|---|
| 电量 | IOPS `Current Capacity` / `Max Capacity` | % | 80 / 100 |
| 外接电源 | IOPS `Power Source State == "AC Power"` | — | AC Power |
| 正在充电 | IOPS `Is Charging` | — | false |
| 剩余时间（放电） | IOPS `Time to Empty`，仅在使用电池时 | 分钟 | 接电时为 0 |
| 剩余时间（充电） | IOPS `Time to Full Charge`，仅在充电时 | 分钟 | 未充电时为 0 |
| 电池电压 | IORegistry `AppleSmartBattery.Voltage` | mV | 12244 |
| 电池电流 | IORegistry `AppleSmartBattery.Amperage`，负数为放电 | mA | 0 |
| 电池功率 | IORegistry `PowerTelemetryData.BatteryPower`，正数充电、负数放电 | mW | 0 |
| 输入功率 | `PowerTelemetryData.SystemPowerIn` | mW | 14514 |
| 系统功率 | `PowerTelemetryData.SystemLoad` | mW | 14514 |
| 输入电压 | `PowerTelemetryData.SystemVoltageIn` | mV | 28008 |
| 输入电流 | `PowerTelemetryData.SystemCurrentIn` | mA | 518 |
| 遥测更新时间 | IORegistry `AppleSmartBattery.UpdateTime` | Unix 秒 | 约每 60 秒变化一次 |
| 电池温度 | IORegistry `AppleSmartBatteryPack` 节点的 `BatteryData.Temperature` ÷ 100 | °C | 2669 → 26.69 |
| 满充容量 | `AppleSmartBattery.BatteryData.FullChargeCapacity` | mAh | 7942 |
| 设计容量 | `AppleSmartBattery.BatteryData.DesignCapacity` | mAh | 8694 |
| 容量比 | 满充容量 ÷ 设计容量 | % | 91.4 |
| 系统最大容量 | `system_profiler SPPowerDataType -json` 中 `spbattery_information` 的 `sppower_battery_health_info.sppower_battery_health_maximum_capacity` | % | "95%" |
| 健康状态 | 同上，`sppower_battery_health_info.sppower_battery_health` | — | "Good" |
| 循环次数 | `AppleSmartBattery.CycleCount` | 次 | 68 |
| 设计循环次数 | `AppleSmartBattery.DesignCycleCount9C` | 次 | 1000 |
| 充电器功率、名称、厂商 | `IOPSCopyExternalPowerAdapterDetails()` 的 `Watts`、`Name`、`Manufacturer` | W | 140 / 140W USB-C Power Adapter / Apple Inc. |
| 低电量模式 | `ProcessInfo.processInfo.isLowPowerModeEnabled`，监听 `NSProcessInfoPowerStateDidChange` | — | false |
| 系统充电上限 | 见第 6 节 | % | 80 |

解析规则：

- IORegistry 的整数按有符号 64 位解析。`ioreg` 显示为很大的正数（如 `18446744073624641601`）的值实际是负数。
- 剩余时间：`≤ 0` 或 `≥ 65535` 视为没有值。
- 不使用的字段：IOPS 的 `DesignCycleCount`（本机返回 300，与 IORegistry 的 1000 不一致）、`AdapterEfficiencyLoss`、`AdapterDetails` 里的电压电流（是协商参数，不是实时测量）。
- 读取 Pack 节点用 `IOServiceNameMatching("AppleSmartBatteryPack")`，和 Stats 的做法一致。
- 没有电池的 Mac（如 Mac mini、Mac Studio）：IOPS 列表里没有 `Type == "InternalBattery"` 的电源时，菜单栏和面板只显示“未检测到电池”，不采样、不写库。

插电未充电时本机读数满足 `SystemPowerIn = SystemLoad + BatteryPower`（14514 = 14514 + 0）。界面直接显示三个原始值，不做配平计算。

## 6. 系统充电上限

macOS 26.4+ 的 Apple Silicon 机型支持在“系统设置 → 电池”里设定充电上限（80%–100%，步长 5）。Apple 没有公开读取接口，有两个私有来源，按顺序使用。

**PowerUI（优先）**：私有框架 `/System/Library/PrivateFrameworks/PowerUI.framework` 的 `PowerUISmartChargeClient`，普通用户权限可读，只调用以下读取方法（实现见 `BatteryCore/PowerUIChargeLimit.swift`）：

| 方法 | 类型编码 | 本机结果 |
|---|---|---|
| `initWithClientName:` | `@24@0:8@16` | — |
| `isMCLSupported` | `B16@0:8` | YES |
| `isMCLCurrentlyEnabled:` | `Q24@0:8^@16` | 1 |
| `getMCLLimitWithError:` | `C24@0:8^@16` | 80 |
| `availableChargeLimitsWithError:` | `@24@0:8^@16` | 80, 85, 90, 95, 100 |

- 框架、类或任一方法缺失，或类型编码与上表不一致时，视为 PowerUI 不可用。
- 不支持 → “不支持”；支持且未开启 → “关闭”；开启且上限为 50–100 的整数 → 采用该值；开关或上限读取出错 → 退回读文件。
- 关闭后 `getMCLLimitWithError:` 返回 100，开关只看 `isMCLCurrentlyEnabled:`。`currentChargeLimit:` 本机始终返回 100，不使用。
- `availableChargeLimitsWithError:` 的结果（只保留 50–100）存为快照的 `chargeLimitOptions`，作为面板和设置页的档位。

**写入（v2 第一项）**：与“系统设置 → 电池”修改的是同一项设置（经 PowerUIAgent 写入，owner 相同），普通用户、ad-hoc 签名加 Hardened Runtime 可以直接调用，不需要 helper。实验记录见 `docs/v2充电控制技术调研.md`。实现见 `BatteryCore/ChargeLimit.swift`、`PowerUIChargeLimit.swift`。

| 方法 | 类型编码 | 用途 |
|---|---|---|
| `setMCLLimit:error:` | `B28@0:8C16^@20` | 修改上限，只在已开启时调用，值取可选档位 |
| `enableMCL:` | `B24@0:8^@16` | 开启，系统恢复关闭前的上限 |
| `disableMCL:` | `B24@0:8^@16` | 关闭 |

- 读取可用且三个写入方法的类型编码都与上表一致时才提供控制，否则只读显示。
- 写入在采样 actor 中执行，完成后立即完整读取一次刷新界面。以 PowerUI 读回为准判断是否生效，powerd 文件会延迟几秒更新，不用来判断。方法返回失败、给出错误或读回不符时，界面提示“未能修改充电上限”。
- 检测到 AlDente（Bundle ID 前缀 `com.apphousekitchen.aldente`）正在运行时禁用控制并说明原因，避免两套工具同时控制充电。AlDente 退出后可能仍保持暂停充电，仅凭进程无法判断，这种情况不处理。
- Hachibu 没有自己的充电状态：退出、崩溃时不需要恢复任何设置。
- 不做：临时充满一次（`temporarilyDisableMCL:` 期间读数为“开启，上限 100”，与用户设为 100 无法区分）、低于 80% 的上限。

**充电上限文件（退回）**：设定值同时保存在：

```text
/Library/Preferences/com.apple.powerd.charging.plist
  policies：NSKeyedArchiver 归档的 ChargeCtrlPolicy 数组
  本机：reason = "manualChargeLimit", soclimit = 80, isEndOfCharge = true
```

普通用户权限可以读取。这是私有格式，读取规则：

- 文件存在、能解档、找到 `reason == "manualChargeLimit"` 且 `soclimit` 为 50–100 的整数时，采用该值。
- 其他任何情况都视为“未知”，不报错、不提示。macOS 26.4 以前的系统没有这个文件，也走这条路径。
- 每次采样时读取 PowerUI 和文件，两者都写进诊断导出。

AlDente 等第三方工具通过 SMC 停止充电，不会写这个文件。所以“接电、不充电”不能只靠这个文件判断原因，按第 7 节的规则显示状态。

## 7. 状态文字与面板显示

状态按顺序匹配，用第一条符合的：

| 条件 | 中文 | 英文 |
|---|---|---|
| 未接外接电源 | 使用电池 | On Battery |
| 接电，`Is Charging = true` | 充电中 | Charging |
| 接电，`BatteryPower < -500 mW` | 已接电，电量下降中 | Plugged In, Draining |
| 接电，未充电，电量 = 100% | 已充满 | Fully Charged |
| 接电，未充电，充电上限已开启，且电量 ≥ 上限 − 5 | 已达到充电上限（80%） | Charge Limit Reached (80%) |
| 其他接电情况 | 已接电，未充电 | Plugged In, Not Charging |

`ChargerData.NotChargingReason` 不参与判断，只写进诊断导出。

“上限 − 5”依据 Apple 文档 102338：达到上限后，电量下降超过 5% 才恢复充电，这个区间内系统处于按上限暂停充电的状态。

面板其他显示规则：

- 温度标签：温度达到或超过温度提醒阈值（第 12 节）时显示“偏高”，否则不显示标签。不使用“正常”这类没有依据的判断。
- 电池健康：系统最大容量、满充容量、循环次数三列；健康状态显示在标题行右侧，`"Good"` 显示为“状态良好”，其他值原样显示英文原文。不显示设计循环次数（`DesignCycleCount9C`），它只写进诊断导出。
- 剩余时间：显示在电量卡片的说明行。使用电池时显示 `Time to Empty`，充电中显示 `Time to Full Charge`，其他状态显示“—”。

## 8. 功率流向图

参照 AlDente 的样式，分三段：左侧供电方 → 中间 MacBook → 右侧用电方。电池功率绝对值小于 500 mW 时视为 0。A = `SystemPowerIn`，L = `SystemLoad`，B = `BatteryPower`。

| 情况 | 供电方（从上到下） | 用电方（从上到下） | MacBook 节点 |
|---|---|---|---|
| 接电，B > 0 | 充电器 A | 系统 L，电池 \|B\| | A |
| 接电，B = 0 或读不到 | 充电器 A | 系统 L | L |
| 接电，B < 0 | 电池 \|B\|，充电器 A | 系统 L | L |
| 未接电 | 电池 \|B\| | 系统 L | L |

- 每条流带的宽度和上面的数值都取对应节点的原始读数，不做配平，两侧合计不一定相等。MacBook 节点取只有一条流带的那一侧的读数（充电时为 A，其他情况为 L）。
- 未接电时不画充电器节点。
- 比例：两侧用同一比例，合计较大的一侧（含两个节点之间 14pt 的间距）占图高的 80%，所以图的粗细不表示绝对功率。每条流带在侧边最窄 3pt，到 MacBook 一侧按 55% 收窄，两侧的流带在 MacBook 处首尾相接、整体垂直居中。
- 节点画成细竖条：侧边宽 5pt、高度等于流带在该侧的宽度，MacBook 宽 6pt、高度为两侧收窄后合计中较大的一个。一侧的节点从上到下排开，整体垂直居中。
- 数值用 W、一位小数，缺失显示“—”。侧边节点的图标和数值写在竖条外侧（左侧节点在左、右侧节点在右，图标在上、数值在下，占宽 46pt）；同一侧两个标签离得太近时以中点为准向两边推开，再整体移回图内。MacBook 的图标写在竖条上方，数值写在下方。
- 不再显示流向图下方的说明句，数值已经写在节点旁。
- 读数变化时流带宽度用弹簧动画过渡，节点出现、消失时淡入淡出（19.6）。
- 面板关闭时停止光点动画（19.6）。

## 9. 采样

| 触发 | 动作 |
|---|---|
| `IOPSCreateLimitedPowerNotification`（插拔）及 `IOPSNotificationCreateRunLoopSource`（电量/剩余时间）回调 | 先独立读取 IOPS 状态，再安排完整读取；合并重复的完整读取请求 |
| 唤醒（`NSWorkspace.didWakeNotification`）、面板打开、应用激活、低电量模式变化 | 先快速读取 IOPS 状态，再完整读取一次 |
| 面板打开 | 每 10 秒读取 |
| 面板关闭 | 每 60 秒读取，timer leeway 10 秒 |
| 启动时、之后每小时 | 运行一次 `system_profiler`（本机耗时约 0.08 秒），用 `Process` 异步执行，超时 10 秒 |

完整读取包括 IOPS、IORegistry 两个节点、充电器信息、PowerUI 和充电上限文件。IORegistry 节点用 `IORegistryEntryCreateCFProperties` 一次读完。

IOPS 快速读取只更新电量、接电/充电、剩余时间和低电量模式，不读取 IORegistry、PowerUI 或充电上限文件，也不等待采样 actor。保留已有功率、温度、遥测时间等完整读数；明确拔线时立即清除旧的充电器信息。读取失败保留原状态，成功但无内置电池与读取失败分开处理。启动时也先快速读取。

电源通知后立即读取，并在约 0.25、1、3 秒时补读 IOPS，以覆盖通知与状态缓存不同步的情况；新事件取消上一次的补读任务。没有事件时仍按原 10/60 秒周期采样，不增加常驻轮询。重复通知的完整读取合并为一个执行中请求及最多一个待刷新请求。

完整采样和快速读取都在开始读取时记时间；较旧的快速结果不能覆盖较新的完整或快速状态。完整采样结束时，将它开始之后读到的新 IOPS 状态合并进界面，避免较慢的返回覆盖插拔结果。快速更新不延长完整数据的新鲜度，不重复触发温度提醒，也不增加写库频率；数据库仍由完整采样驱动。实际通知送达和插拔至界面的耗时需真机验收，不以测试中的模拟接口耗时替代。

`PowerTelemetryData` 约每 60 秒刷新一次，和 `UpdateTime` 同步变化。面板上的功率旁显示“更新于 X 秒前”，根据 `UpdateTime` 计算。

菜单栏文字使用等宽数字，显示的字符串没变就不更新。菜单栏可选显示：电量（%）、系统功率（W，一位小数）、温度（°C，一位小数）。

图标只提供 macOS、iOS 两种电池外观，默认 macOS。两者以 macOS 27、iOS 27 为参考独立绘制连续圆角轮廓、端帽和状态标记，不嵌入 AlDente、Apple UI Kit 或 ControlCenter 的原始资源，不依赖私有资源路径。macOS 主体 23×12pt，iOS 主体约 26.33×13.67pt；图标画布固定为 26×18pt、30×18pt，不因充电状态或数字位数改变宽度。电池填充随实际电量变化；菜单栏标记直接使用 IOPS 的接电、充电字段：接电且充电显示闪电，接电未充电显示竖向插头（包括接电放电），未接电或接电状态未知不显示标记。不用更新较慢的电池功率决定接电标记；第 7 节的面板状态仍按原规则判断。电量未知显示问号，不用 0 代替。

iOS 在电池内显示系统粗体电量数字；选择电量读数时不在图标旁重复显示百分比，选择功率或温度时保留外部读数。无障碍文字包含图标内电量和选定读数。正常图标使用模板图像跟随菜单栏外观；低电量模式优先用系统黄，iOS 充电为系统绿，其他电量 ≤ 20% 为系统红。颜色图标响应菜单栏深浅外观。先在离屏位图内完成数字和标记的挖空，提供 1×、2× 图像，再交给菜单栏。只有图标相关状态变化时重绘。旧 `brand`、`batteryColored`、`hidden` 及未知样式值回退 macOS，原 `battery`、`ios` 值和读数选择保留。素材来源和静态核对范围见 `新功能需求.md` 第 4 节。

休眠期间不补数据，唤醒后从实际时间继续记录。不阻止系统休眠，不使用 `.latencyCritical`。

## 10. 存储

数据库文件：`~/Library/Application Support/<Bundle ID>/history.sqlite`。时间戳存 UTC Unix 秒。

```text
minute_samples        最近 7 天
  ts                  INTEGER PRIMARY KEY   采样时间，按分钟取整
  percent             INTEGER
  is_external         INTEGER (0/1)
  is_charging         INTEGER (0/1)
  system_load_mw      INTEGER
  battery_power_mw    INTEGER
  power_in_mw         INTEGER
  temperature_c       REAL
  voltage_mv          INTEGER
  amperage_ma         INTEGER

hourly_samples        长期保存
  hour_ts             INTEGER PRIMARY KEY   小时起点
  sample_count        INTEGER
  external_minutes    INTEGER               该小时内接电的分钟数
  percent_avg / percent_min / percent_max
  system_load_avg_mw / system_load_max_mw
  temperature_avg_c / temperature_max_c

daily_samples         长期保存
  day                 TEXT PRIMARY KEY      本地日期 YYYY-MM-DD
  system_max_capacity_pct   INTEGER
  full_charge_mah     INTEGER
  design_mah          INTEGER
  cycle_count         INTEGER
  updated_at          INTEGER
```

- `minute_samples` 由一个独立的每分钟定时器写入，每分钟一行，写入当时最近一次读取的值。面板打开时的 10 秒读取只更新界面，不写库。主键冲突时覆盖（`INSERT OR REPLACE`）。
- `daily_samples` 在每次 `system_profiler` 读取后写入：系统最大容量来自 `system_profiler`，满充容量、设计容量、循环次数来自当时的 IORegistry 读数，按当天日期 upsert，一天保留最后的值。关机的日子没有记录。
- 聚合：启动时和每小时执行一次。在一个事务里，把所有早于“现在 − 7 天”且整小时结束的分钟数据按小时汇总 upsert 进 `hourly_samples`，再删除这些分钟数据。主键保证重复执行结果相同。没有分钟数据的小时不生成行。
- 平均值、最大值只统计非 `NULL` 的样本；全部为 `NULL` 时结果为 `NULL`。
- 迁移用 GRDB `DatabaseMigrator`，已发布的迁移只追加不修改。

## 11. 历史曲线

| 组 | 时间范围 | 数据 | 绘制 |
|---|---|---|---|
| 近期 | 1 小时 | `minute_samples` 原始点 | 约 60 点 |
| 近期 | 24 小时 | `minute_samples` 原始点 | 约 1440 点 |
| 近期 | 7 天 | `minute_samples` 按小时 GROUP BY 求平均（`HistoryStore.minuteSamplesByHour`，返回 `HourlyAverage`） | 约 168 点 |
| 长期 | 30 天 / 1 年 / 全部 | `daily_samples` | 每天一点 |

- 近期组六张图：电量、电池温度、系统功率、电池功率（`battery_power_mw`，充电为正、放电为负）、充电器输入功率（`power_in_mw`）、电池电压（`voltage_mv`）。接电时段（`is_external = 1` 的连续区间）画底色。7 天范围的电池功率是每小时的平均净功率，充放电会相互抵消。
- 长期组四张图：系统最大容量、容量比（`full_charge_mah / design_mah`，任一缺失的那天没有点）、满充容量、循环次数。系统最大容量是整数百分比，和循环次数一样画阶梯线。
- 阶梯线用 `.interpolationMethod(.stepStart)` 还是 `.stepEnd`，用两点测试数据确认：台阶应落在数值变化的那一天。
- 相邻两点间隔超过 3 个采样周期时断开曲线，不连线跨过缺口。
- 所选范围早于第一条记录时，横轴保持完整，早于第一条记录的区间标“未记录”。
- 悬停：`chartOverlay` + `onContinuousHover`，图上方的读数换成最近一个点的值和时间，同组同步。
- 工具栏标题下方的“最近更新 HH:mm”取最近一次采样时间。
- 侧栏底部“自 {日期} 开始记录 · 已记录 {N} 天”：日期取 `daily_samples` 最早的一天，N 为 `daily_samples` 的行数。

## 12. 通知

两种提醒，开关和阈值在通知页修改：

| 提醒 | 默认阈值 | 触发 | 恢复 |
|---|---|---|---|
| 电池温度过高 | 40°C | 连续 3 分钟高于阈值，提醒一次 | 连续 5 分钟低于阈值 − 2°C 后，允许再次提醒 |
| 健康度低 | 80% | 当天系统最大容量低于阈值，提醒一次 | 不再重复提醒，除非用户调整阈值 |

提醒状态（是否已提醒）存在 `UserDefaults`，重启后保留。读数缺失不算恢复。

- 温度按读数时间计算持续时长。读数缺失，或相邻两次读数间隔超过 90 秒（例如休眠），两段计时都从头开始。
- 健康度在每次 `system_profiler` 读取后判定（约每小时一次）。记下提醒时的阈值，阈值改成别的值后允许再次提醒。
- 系统通知未允许时不判定，提醒状态保持不变。授权变为允许时，用已有的健康度读数立即判定一次。
- 启动时如果有提醒打开且从未询问过授权，请求通知授权。同类提醒使用同一个通知标识符，新的替换旧的。

通知页显示：系统通知授权状态（未询问时给“允许通知”按钮，被拒绝时给“打开通知设置”按钮）；两种提醒的开关、阈值、当前读数和状态（关闭 / 等待中 / 已提醒）。

## 18. 为 v2、v3 预留

- v2 充电控制：本机（MacBookPro18,1，固件 20457.1.29，macOS 27.0.1）只读探测结果是传统限充 SMC key（CH0B、CH0C、CHTE、CHWA、BCLM 等）已不存在或拒绝访问，只剩切断适配器供电的 CHIE。所以 v2 以控制系统原生充电上限为主（80%–100%），写入走 PowerUI：`setMCLLimit:error:` 设上限，`enableMCL:` / `disableMCL:` 开关，调用前与读取一样校验类型编码。2026-10-24 本机实验确认，普通用户、ad-hoc 签名加 Hardened Runtime 的进程可以直接写入，不需要 helper 和 entitlement，也不用 Shortcuts。关闭后上限读数为 100，重新开启会恢复关闭前的值；写入后以 PowerUI 读回为准，powerd 文件会延迟几秒更新。低于 80% 的上限、航行模式、强制放电只能靠 CHIE 加 root helper，作为用户主动开启的高级功能，另行验证 ad-hoc 签名下 helper 的安装方式后再做。检测到 AlDente 运行时不启用控制。详见 `docs/v2充电控制技术调研.md`。第一项（开关与 80%–100% 档位，在面板和设置页）已实现，规则见第 6 节；临时充满一次暂不做，低于 80% 不进 v2。
- v3 导入 AlDente 历史数据：AlDente 的统计数据库经过 SQLCipher 加密，Hachibu 不提供解密方法或让用户自行解密的指引。只导入有长期价值、口径明确的每日指标（满充容量、循环次数、系统最大容量），导入时过滤异常值，导入的数据单独存放并能按批次删除。数据来源待定：先确认 AlDente 自身能否导出历史，没有合法来源时 v3 改为公开格式的通用导入或延期。

## 19. 界面视觉（第三版改版，已实现）

本节描述界面的视觉和布局，2026-10-25 按第三版改版稿重写。显示哪些数据仍按第 7、8、11 节。按本节改代码后更新 19.8。

风格以 macOS 26 的液态玻璃为准：面板底板、按钮、主窗口侧栏和工具栏交给系统材质；面板内容和历史曲线放在浅色圆角块里。

### 19.1 原则

- 面板内容按用途分块：每块是玻璃底板上的浅色圆角块（浅色模式白色 60% 不透明，深色模式白色 7%，圆角 18，0.5pt 细描边），块间距 8。主窗口每张曲线一张卡片。
- 单行文字一律不折行：`lineLimit(1)`，空间不够时缩小字号（`minimumScaleFactor`），只有说明句（AlDente 提示、写入失败）可以换行。
- 颜色少而固定，用法见 19.4。不用纹样、纸质纹理等装饰元素。
- 不再使用碗形图形，碗只保留在 logo 和应用图标里。

### 19.2 菜单栏面板

宽 360pt，一整块玻璃底板（`NSGlassEffectView`，圆角 28），内边距 12。从上到下：

| 块 | 内容与样式 |
|---|---|
| 功率 | 标题行左侧为带 SF Symbol 的状态文字（第 7 节），右侧为“X 秒前更新”。下面是三段功率流向图（第 8 节），高 156pt。面板的视觉重点 |
| 电量 / 温度 / 功率 | 一行三张等宽卡片，每张为彩色图标 + 小标签、22pt 数值、一行小字说明。电量卡片的说明为剩余时间；温度卡片说明为“电池”，达到阈值时标签行右侧显示“偏高”；功率卡片显示 `SystemLoad`，说明为“系统” |
| 系统充电上限 | 只在可以写入时出现（第 6 节）。标题行右侧为小号开关（`.controlSize(.small)`）；开启时下方为铺满宽度的分段档位（80% / 85% / … / 100%）。系统 `.segmented` 在 macOS 上不能铺满，档位用按钮自己画（`LimitSegments`）：浅灰底槽圆角 9，选中项为白色圆角块加阴影、粗体。AlDente 运行时禁用并用小字说明，写入失败时红字提示 |
| 电池健康 | 标题行右侧为健康状态。一行三列：系统最大容量、满充容量（mAh）、循环次数。循环次数不显示设计循环次数 |
| 详细数据 | 默认折叠，折叠时标题行右侧提示“电压、电流、充电器”（未接电时不含充电器）。展开后为：电池电压、电池电流、电池功率（充电带“+”，放电带“−”）；设计容量、容量比（满充 / 设计）；接电时再加充电器（名称，读不到时用额定功率，额定功率和厂商放在悬停提示里）和输入电压 · 电流。展开状态存 `UserDefaults` 的 `panelDetailsExpanded` |
| 底部 | 低电量模式状态胶囊（高 32，显示“低电量模式 开 / 关”；开启时黄色底，关闭时为浅色块底、次要色）、占满剩余宽度的“打开主窗口”玻璃按钮、退出图标按钮（`power` 符号，悬停显示“退出”，设置无障碍标签） |

不再有电量头部：电量数字放进电量卡片，充电上限只体现在状态文字和充电上限块里。

### 19.3 主窗口

- 默认大小 1200 × 840，最小 960 × 660。窗口位置和大小由 `setFrameAutosaveName("MainWindow")` 记住，已经打开过窗口的用户保留原来的大小。
- 窗口加 `.fullSizeContentView` 和 `NSToolbar`（`toolbarStyle = .unified`），`NSHostingView.sceneBridgingOptions` 包含 `.toolbars` 和 `.title`，让 `NavigationSplitView` 的侧栏由系统画成悬浮玻璃。侧栏宽 200–280pt，默认 232pt，底部的记录概况放在浅色圆角块里，第一行“已记录 N 天”，第二行“自某日开始记录”。
- 页面标题用 `navigationTitle` 显示在工具栏，内容区不再手写大标题。
- 历史曲线页：组标题 20pt 粗体，两组之间间距 40，时间范围选择器留在各组标题行。每组一行两张图（`LazyVGrid` 两列，列间距 18、行间距 22）。
- 每张图：上方为颜色圆点 + 指标名（12pt）、26pt 读数，右侧为读数对应的时间（11.5pt）；电池功率图的圆点左半绿、右半橙。长期组标题写明口径：“最大容量（系统）”“容量比（满充 / 设计）”，电池功率图标题为“电池功率（充电为正，放电为负）”。下方卡片圆角 16，里面是曲线，图高 200pt。曲线线宽 2pt，下方同色渐变面积（不透明度 0.28 到 0）。电池功率图正值绿色、负值橙色，面积以 0 为基线，并画一条 0 线。
- 悬停：同组几张图同步显示竖线和圆点，上方读数和时间换成悬停处最近一个点的值，时间改为主色加粗。不再显示浮动气泡。
- 通知页、设置页继续用系统分组表单（`.formStyle(.grouped)`）。

### 19.5 字体

界面只用系统字体（SF、苹方），品牌字体只出现在 logo 图片里。数值用 `.rounded` 设计和等宽数字；面板卡片数值 22pt semibold，电池健康数值 19pt，流向图侧边节点数值 12.5pt bold、MacBook 节点数值 12pt bold；主窗口曲线读数 26pt。macOS 的 `.caption` 只有 10pt，比改版稿小，面板和主窗口的文字直接写字号：面板标题行状态文字 13pt semibold，块标题 12pt semibold，卡片和健康三列的标签、“X 秒前更新”、低电量模式 11.5pt，卡片说明行 11pt，详细数据各行 12pt，档位 12pt；侧栏记录概况 12pt semibold / 11.5pt。标签用次要色。

### 19.6 动效

- 电量、功率、温度等数值变化用 `.contentTransition(.numericText())`。
- 充电上限档位、详细数据的出现和消失用弹簧动画。
- 功率流向图：流带里有带拖尾的白色光点沿流带从左往右移动，按流带宽度分 1–4 条轨道，各轨道的位置、间距（约 44pt）、速度（26–38pt/秒）不同，靠近两端时淡出。用 `TimelineView(.animation)` 驱动，约 30 帧每秒。面板关闭时（`BatteryMonitor.isPanelVisible` 为 false）暂停。读数变化时流带宽度用弹簧动画（0.7 秒）过渡。
- 玻璃按钮有悬停和按压反馈。
- 系统开启“减弱动态效果”时，弹簧和位移改为淡入淡出，功率流光点不播放。

### 19.7 旧系统与实现注意

- macOS 14、15 没有液态玻璃：底板用 `NSVisualEffectView`，按钮改用 `.bordered`，布局和颜色不变。`glassEffect` 等 API 用 `if #available(macOS 26, *)` 分支。
- 面板大小由 `PanelController.fitToContent()` 设置。内容展开、收起时窗口尺寸跟着动画。
- 面板各状态（使用电池、充电中、接电放电、接电轻微放电、接电未充电、上限关闭且 AlDente 运行、无电池、数据缺失）写 `#Preview`，用示例数据在 Xcode 预览里检查视觉。主窗口各页同样写 `#Preview`，数据不读硬件、不写 App 的设置。
