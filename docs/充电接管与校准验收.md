# 充电接管与校准验收

2026-11-09。v0.1.8 的功能代码已实现，实际运行待真机验收。代码与静态渲染的检查不等于实际充电行为验收。

## 自动校验

```bash
swift build --package-path Packages/HachibuKit --build-tests
swift test --package-path Packages/HachibuKit
xcodegen generate
xcodebuild -project Hachibu.xcodeproj -scheme Hachibu -configuration Debug build
HACHIBU_RENDER_DIR=/private/tmp/hachibu-charge-render swift test --package-path Packages/HachibuKit --filter 'ChargeControlRenderTests|HistoryRenderTests.renderPolicyBands|SettingsRenderTests.renderNotifications'
```

- `CalibrationTests`：六阶段完整流程、充满条件、保持累计、拔电/系统策略/写入失败/缺 helper 的暂停、重启后继续、跳步和重做、放电时间估算。
- `ManagedChargeLimitTests`：校准/保持/目标的优先级、待批准时的 80% 回退、PowerUI 和登记双重确认、登记解析、系统策略、偏好和恢复标记的类型检查。
- `ChargeControlMonitorTests`：进入/退出/切回系统、外部变更写回、失败节流、系统策略期间禁止写入、校准暂停/取消/退出、连续取消重开时的数据库记录隔离。写入均使用内存假系统，不修改本机设置。
- 现有 HistoryStore、通知、诊断及充电保持等测试继续覆盖相关路径。
- 静态渲染覆盖中文浅色/深色、英文浅色的接管、待批准、系统策略、校准放电、上次退出未完成、校准记录，以及通知页和历史底色。图片输出到上述目录；已人工看图，尚待用户确认定稿。

渲染使用纯色近似材质和静态系统控件，不验证真实玻璃、动画、窗口焦点或按钮操作。按仓库约定不自动启动 App、不注册或批准 helper、不运行完整校准。

## 日志与诊断

操作后先在设置页导出诊断 JSON，包含模式、目标、helper 注册与偏好状态、`pmset` 原文及校准进度。终端可只读查看登记与日志：

```bash
pmset -g battlimit
/usr/bin/log show --last 30m --style compact --predicate 'category == "ChargeControl" AND (subsystem == "io.github.nanvon.hachibu" OR subsystem == "io.github.nanvon.hachibu.helper")'
```

核对每次写入/读回、策略开始/结束、校准步骤与暂停原因、helper 注册状态和续约超时。诊断 JSON 不包含完整统一日志，提交问题时同时附上对应时间段的日志。新的系统大版本验证通过前不开放低于 80% 的写入。
